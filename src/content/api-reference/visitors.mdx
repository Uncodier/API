# Visitors

Browser tracking usually goes through CORS (allowed origin, no API key). Server-to-server needs a key. See [Auth](/concepts/auth-model) and [Website guide](/guides/website-chat-and-tracking).

## List sites / visitors

<div className="endpoint-block">
  <MethodChip method="GET" />
  <code>/api/visitors/sites</code>
</div>

```bash
curl -X GET "https://backend.makinari.com/api/visitors/sites?site_id=YOUR_SITE_ID" \
  -H "Authorization: Bearer YOUR_API_KEY"
```

## Track an event

<div className="endpoint-block">
  <MethodChip method="POST" />
  <code>/api/visitors/track</code>
</div>

Typical body: `site_id`, `event_type`, `event_name`, `url`, `visitor_id`, `session_id`. From the page, the tracking script does this for you.

## Identify

<div className="endpoint-block">
  <MethodChip method="POST" />
  <code>/api/visitors/identify</code>
</div>

Attach a known person to the session (`email`, `firstName`, `lastName`). Client helper: `window.MarketFit.identify(...)`.

## Sessions

- `POST /api/visitors/session` — start / update
- `GET /api/visitors/session` — read
- `POST /api/visitors/session/end` — close
- `POST /api/visitors/session/{session_id}/identify` — bind a lead
- `POST /api/visitors/segment` — add the visitor to a segment
