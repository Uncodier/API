# Reservations

Manage capacity reservations and find available slots for reservable items. `action="create"` books the slot **and** creates a pending `sale_order` (same commercial path as checkout for a single reservable line), linked via `sale_order_item_id`. The response includes `order_id` and `sale_id` so you can charge with `checkout.create_payment_link`. Do not also call `checkout.create_order` for the same slot. Mixed carts (product + slot) still use checkout.

Use `action="get_available_slots"` to query inventory for a date range (requires `catalog_item_id`, `from_date`, `to_date`). Use `action="create"` to book (requires `catalog_item_id`, `lead_id`, `start_time`, `end_time`). Use `action="update"` to reschedule, change status (e.g. to `cancelled`), or reassign `lead_id`. `get`/`update` require the reservation UUID in `id` (alias: `reservation_id`). On update, the current reservation is excluded from the capacity check — keep `quantity` as the real seat count.

## Input Schema

| Parameter | Type | Description |
| :--- | :--- | :--- |
| action | string | Action to perform: list, get, get_available_slots, create, update |
| id | string | Reservation UUID (required for get, update) |
| reservation_id | string | Alias of `id`. Either field is accepted for get/update |
| site_id | string | Seller site UUID (defaults to current site) |
| catalog_item_id | string | Catalog item UUID (required for create, get_available_slots) |
| lead_id | string | Lead UUID attached to the reservation (required for create; reassignable on update) |
| from_date | string | Start date for slot query (ISO string, e.g. 2026-07-27) |
| to_date | string | End date for slot query (ISO string) |
| start_time | string | Start time of the reservation (ISO datetime string) |
| end_time | string | End time of the reservation (ISO datetime string) |
| quantity | number | Number of seats/capacity to reserve (default 1) |
| status | string | Status (e.g. pending, confirmed, cancelled) |
| notes | string | Notes (updatable) |
| entitlement_id | string | Entitlement UUID to redeem a pass (creates a $0 sale_order line) |
| limit | number | Limit results for list |
| offset | number | Offset results for list |

## Validation

- `get_available_slots` uses the target item's `reservation_schedules` for the slot grid, then subtracts overlapping `pending`/`confirmed` reservations across the parent and all variants of that resource. When the parent `redeem_assignment_mode` is `round_robin`, available seats are the number of free `user_choice` peer families (named barbers) on the same site.
- `create` asserts the slot, then inserts `sales`, `sale_orders`, `sale_order_items`, and `reservations` (with `sale_order_item_id`). Pass redemptions (`entitlement_id`) still create the order at unit price 0.
- `update` requires at least one of `status`, `start_time`, `end_time`, `quantity`, `notes`, `lead_id`. Capacity on reschedule excludes the reservation being updated (`WHERE id != reservation_id`). Cancelling (status=`cancelled`) frees capacity in the slots.

## Example

```json
{
  "action": "get_available_slots",
  "catalog_item_id": "CAT_ITEM_ID",
  "from_date": "2026-07-27",
  "to_date": "2026-07-31",
  "quantity": 2
}
```

```json
{
  "action": "create",
  "catalog_item_id": "CAT_ITEM_ID",
  "lead_id": "LEAD_ID",
  "start_time": "2026-07-27T15:00:00.000Z",
  "end_time": "2026-07-27T16:00:00.000Z"
}
```

```json
{
  "action": "update",
  "id": "RESERVATION_UUID",
  "status": "cancelled"
}
```
